## 📋 Описание модуля

Модуль интерфейса **«Создать новое пространство»** (`tab_create_workspace`) предоставляет экран создания изолированного рабочего пространства с инициализацией Git, единым экраном параметров и прямым подключением внешних файлов и директорий для слежения без копирования (`copy_to_workspace = false`).

В интерфейсе отсутствует принудительный пошаговый мастер (wizard): параметры репозитория и блок подключения внешних директорий/файлов отображаются одновременно на одном экране, позволяя добавлять источники как до создания пространства (в предварительный список staging), так и после него.

---

## 🎯 Основные возможности

1. **Единый экран создания без пошагового мастера**:
   - Параметры пространства (имя, язык, рабочая папка, описание) и блок подключения внешних объектов объединены в один доступный экран.
   - Поддержка предварительного добавления (staging) директорий и файлов: выбранные пути накапливаются в списке и автоматически ставятся на версионный учёт сразу при создании пространства.

2. **Инициализация Git-репозитория и Obsidian Vault**:
   - Поля ввода имени, описания и рабочей директории на диске.
   - Автоматический вызов `git init`, создание структуры `.workspace/config.json` и базовых файлов Obsidian Vault (`_Knowledge_Base.md`).

3. **Слежение за изменениями на месте по умолчанию (`copy_to_workspace = false`)**:
   - Файлы и папки остаются на своих исходных местах на диске, а Git отслеживает их через легковесные манифесты `.tracked.md` и текстовые слепки `.extracted_snapshots/*.snapshot`.
   - Мгновенный системный выбор папок и файлов через REST API (`/browse-folder`, `/browse-file`) и быстрый ввод по клавише <kbd>Enter</kbd>.

4. **Носимый режим с привязкой к имени компьютера (`\\<HOST_NAME>\<PATH>`)**:
   - Для каждого внешнего файла и папки автоматически фиксируются `host_name` (имя компьютера) и полный квалифицированный путь `\\<HOST_NAME>\<Drive>:\<Path>`.
   - В таблице подключённых источников отображаются бейдж хоста (`🖥️ <HOST>`) и статус доступности (`Доступен`, `На другом ПК (<HOST>)`, `Недоступен`).

## 🔌 API эндпоинты

- `POST /api/v1/workspaces` — создание пространства (`workspace_id`, `name`, `custom_path`, `description`, `language`).
- `POST /api/v1/workspaces/{workspace_id}/items` — подключение директорий и файлов (`copy_to_workspace = false` по умолчанию).
- `GET /api/v1/workspaces/{workspace_id}/sources` — получение списка отслеживаемых источников с полями `host_name`, `qualified_path`, `status`, `is_current_host`.
- `DELETE /api/v1/workspaces/{workspace_id}/sources/{source_id}` — исключение источника из отслеживания.
- `POST /api/v1/workspaces/browse-folder` — нативный диалог выбора папки на диске.
- `POST /api/v1/workspaces/browse-file` — нативный диалог выбора файла на диске.
