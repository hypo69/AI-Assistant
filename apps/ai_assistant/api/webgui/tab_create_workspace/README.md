## 📋 Описание модуля

Модуль интерфейса **«Создать новое пространство»** (`tab_create_workspace`) и сопутствующий модальный мастер (`js/workspace_wizard.js`) предоставляют экран создания изолированного рабочего пространства с инициализацией Git, поддержкой носимого (USB-флешка) режима и подключением внешних файлов и директорий для слежения без копирования.

---

## 🎯 Основные возможности

1. **Инициализация Git-репозитория и Obsidian Vault**:
   - Поля ввода имени, описания и рабочей директории на диске.
   - Автоматический вызов `git init`, создание структуры `.workspace/config.json` и базовых файлов Obsidian Vault (`_Knowledge_Base.md`).
2. **Слежение за изменениями на месте по умолчанию (`copy_to_workspace = false`)**:
   - Чекбокс копирования по умолчанию **выключен**: файлы и папки остаются на своих исходных местах на диске, а Git отслеживает их через легковесные манифесты `.tracked.md` и текстовые слепки `.extracted_snapshots/*.snapshot`.
   - При явном включении чекбокса (`copy_to_workspace = true`) файлы физически копируются внутрь каталога рабочей области.
3. **Носимый режим с привязкой к имени компьютера (`\\<HOST_NAME>\<PATH>`)**:
   - Для каждого внешнего файла и папки автоматически фиксируются `host_name` (имя компьютера) и полный квалифицированный путь `\\<HOST_NAME>\<Drive>:\<Path>`.
   - В таблице подключённых источников отображаются бейдж хоста (`🖥️ <HOST>`) и статус доступности (`Доступен`, `На другом ПК (<HOST>)`, `Недоступен`).

## 🔌 API эндпоинты

- `POST /api/v1/workspaces` — создание пространства (`workspace_id`, `name`, `custom_path`, `description`).
- `POST /api/v1/workspaces/{workspace_id}/items` — подключение директорий и файлов (`copy_to_workspace = false` по умолчанию).
- `GET /api/v1/workspaces/{workspace_id}/sources` — получение списка отслеживаемых источников с полями `host_name`, `qualified_path`, `status`, `is_current_host`.
- `DELETE /api/v1/workspaces/{workspace_id}/sources/{source_id}` — исключение источника из отслеживания.
