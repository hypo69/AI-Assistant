## 1. RFC 2119 ключевые слова

Требования к реализации используют стандарт RFC 2119:
- **MUST (ОБЯЗАТЕЛЬНО)** — Абсолютное требование. Нарушение делает код неприемлемым.
- **MUST NOT (ЗАПРЕЩЕНО)** — Абсолютный запрет. Использование **категорически недопустимо**.
- **SHOULD (РЕКОМЕНДУЕТСЯ)** — Следует при отсутствии веских причин для отклонения.
- **MAY (ДОПУСКАЕТСЯ)** — Полностью опциональное действие.

## 2. Фундаментальные архитектурные принципы

### 2.1 Читаемость важнее краткости (Readability Over Cleverness)
Код пишется для людей. **MUST NOT** использовать скрытые трюки синтаксиса, ухудшающие читаемость.

### 2.2 Принцип единственной ответственности (Single Responsibility)
Каждый модуль, класс и функция **MUST** решать **только одну** логическую задачу.

### 2.3 Явное лучше неявного (Explicit is Better than Implicit)
- Зависимости **MUST** передаваться явно (Dependency Injection).
- Глобальное состояние **MUST NOT** использоваться; все параметры **MUST** передаваться через конфигурацию.

### 2.4 Ранний возврат и отказоустойчивость (Early Return & Fail-Fast)
Функции **MUST** завершать выполнение сразу при обнаружении невалидных входных данных:

```python
# ✅ Правильно: Ранний возврат
def process_data(data: dict) -> bool:
    if not data:
        return False
    # Основная логика
    return True

# ❌ Неправильно: Глубокая вложенность
def process_data(data: dict) -> bool:
    if data:
        # Основная логика
        return True
    return False
```

### 2.5 Конфигурация вместо жесткого кодирования (Configuration Over Hardcode)
Все параметры (порты, URL, таймауты, пути) **MUST NOT** быть жестко закодированы. **MUST** считываться из конфига или переменных окружения:

```python
# ✅ Правильно
port = config.port

# ❌ Неправильно
port = 8002
```

### 2.6 Категорический запрет `None` (No None Rule)

**КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** использовать и ссылаться на `None` в исходном коде.

#### 2.6.1 Сигнатуры функций и поля dataclass / моделей

```python
# ❌ ЗАПРЕЩЕНО
def execute(timeout: Optional[int] = None, text: Optional[str] = None) -> None:
    pass

@dataclass
class DocumentFact:
    doc_id: Optional[int] = None
    confidence: Optional[float] = None

# ✅ ОБЯЗАТЕЛЬНО
def execute(timeout: Optional[int] = 0, text: Optional[str] = '') -> Self:
    pass

@dataclass
class DocumentFact:
    doc_id: Optional[int] = 0
    confidence: Optional[float] = 0.0
```

#### 2.6.2 Инициализация переменных

```python
# ❌ ЗАПРЕЩЕНО
result = None
data = None

# ✅ ОБЯЗАТЕЛЬНО
result = False
data = {}
```

#### 2.6.3 Операторы сравнения

```python
# ❌ ЗАПРЕЩЕНО
if value is None:
    pass

# ✅ ОБЯЗАТЕЛЬНО
if not value:
    pass
```

#### 2.6.4 Возвращаемые значения

```python
# ❌ ЗАПРЕЩЕНО
def fetch_data():
    if error:
        return None  # или пустой return
    return data

# ✅ ОБЯЗАТЕЛЬНО
def fetch_data():
    if error:
        return False  # или другое значение по умолчанию
    return data
```

### 2.7 Фиксация времени модификации в шапке файла (File Header Timestamp)
При **любом** изменении исходного кода в файле (Python, JS/TS, CSS, HTML, PowerShell и др.) разработчик/ассистент **MUST** записать или обновить поле `Updated: YYYY-MM-DD HH:MM:SS` в шапке файла с актуальной датой и временем модификации.

## 3. Правила проектирования и устранение Code Smells

### 3.1 Ограничение вложенности (Nesting Limit ≤ 3)
Глубина вложенности циклов и условий **SHOULD NOT** превышать **3 уровней**. Если больше — разбейте на отдельные функции.

### 3.2 DRY: Поиск существующего кода (Prior Art Audit)
**ПЕРЕД** разработкой новой функциональности **MUST** выполнить поиск в кодовой базе:
- Ищите похожие функции, компоненты, утилиты в `apps/ai_assistant/core/`, `apps/common/`, `src/ai/`, `src/utils/`.
- Если существует рабочая реализация на 80%+ — **переиспользуйте или расширьте**, не дублируйте.
- Смотрите [`standards/REUSE.md`](REUSE.md) для полного протокола.

### 3.3 Мертвый код (Dead Code)
Неиспользуемые переменные, импорты, функции **MUST** удаляться сразу. Закомментированный код **MUST NOT** оставляться.

### 3.4 Размер функций и файлов (Лимит 500 строк + 20%)
1. **Ограничение функционального кода**: Любая функция или модуль **MUST NOT** превышать **500 строк функционального кода** (без учета комментариев и docstrings). Допускается превышение не более чем на **+20%** (до 600 строк) при наличии объективной необходимости. Если объем превышает лимит — выполните обязательную декомпозицию на меньшие модули или функции.
2. **Исключение для неразрывных файлов определений**: Ограничение не распространяется на файлы с длинными монолитными определениями, которые по своей сути неразделимы (построение сложных SQL-запросов, декларативные схемы таблиц, крупные шаблоны или конфигурационные пресеты).
3. **Изоляция управления таблицами**: Даже при описании и определении таблиц базы данных управление каждой таблицей **MUST** содержаться в отдельном файле (один файл — одна таблица/репозиторий и её операции/запросы).

### 3.5 Запрет на незаконченный код
Генерация TODO/FIXME комментариев, заглушек `...` вместо логики **MUST NOT** допускаться.

## 8. Стандарты фронтенда и версионирование ассетов (Cache-Busting)

### 8.1 Обязательное обновление версий `?v=...` (Cache-Busting Rule)
Браузеры кешируют JS-скрипты, CSS-стили и HTML-шаблоны вкладок. Чтобы пользователь **гарантированно не получал закешированные старые версии** при изменении фронтенда:

1. **Формат версии:** Строго `?v=YYYYMMDD_vN` (например, `?v=20261101_v1`).
2. **Обязательные места синхронизации версий при редактировании вкладок, стилей и скриптов:**
   - `apps/ai_assistant/api/webgui/index.html` — теги `<link rel="stylesheet">` и `<script type="module" src="...">`.
   - `apps/ai_assistant/api/webgui/css/main.css` — директивы `@import "...?v=YYYYMMDD_vN"`.
   - `apps/ai_assistant/api/webgui/js/main.js` — реестр вкладок `TABS` и импорты модулей.
3. **Правило:** При **ЛЮБОМ** изменении кода JS, стилей CSS или `index.html` во вкладках (`apps/ai_assistant/api/webgui/` или `apps/common/webgui/`), агент **MUST** обновить версию `?v=YYYYMMDD_vN` в точках подключения.
